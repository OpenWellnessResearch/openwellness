Router recipe (`resources/weight.py` after plan 02-04 is the reference): import `Access, authorize` from `..authz.engine` and drop imports left unused; put `access: Access = Depends(authorize("<module>", "<op>"))` on all handlers with ops create, get, patch, delete, undelete, purge, list; pass `access` into `_fetch` and end it with `access.check_record(...)`; patch with `apply_patch(entity, body, principal=access.principal)`; list with `access.scope_list(...)` before `paginate`. `participant`, `study` and `study_message` have `binding` None, so each keeps its own create and does not call `stamp_create`; `study_settings` does call it.

Do not edit `tests/test_policy_matrix.py` or `authz/engine.py`: four other plans run beside this one, and `ROLLED_OUT` detects a router on its own. If the engine appears wrong, stop and report it rather than editing it here.

Facts verified by the planner against the current tree:
- `participant.py` patches with its own `setattr` loop on `body.model_dump(exclude_unset=True)`, and its `ParticipantUpdate` carries `user_id`. `Participant` has no `updated_by` or `updated_at`, so `apply_patch` behaves the same apart from the denylist.
- `participant.py` `_fetch` compares `entity.study_id != study`; keep it, then call `access.check_record`.
- `StudyCreate` and `StudyUpdate` both carry `updated_by` from the body. `apply_patch` now ignores it; create must overwrite it.
- `study_message.py` is not a `BaseOwnerEntity`: create sets `payload["study_id"] = study` and has no `updated_by`. `study_settings.py` is: its owner is `{study}`, and `stamp_create` binds `study_id` to the segment through `binding="study"`.
- `study.py` `lookup` raises `not_found(_COLLECTION, body.name)` for a missing name. A plain `check_record(entity)` denial derives its text from the URL, `/v1/studies:lookup`, which holds no name, so the two bodies would differ; plan 02-04's `name` keyword makes the denial read `studies/<name> not found`, the same bytes.
- `get_for_owner_between` is missing from the Couchbase `study_settings` adapter, so its list raises 500 on a live store. That predates this phase, is reported to the developer, and is out of this plan's scope.
</context>
