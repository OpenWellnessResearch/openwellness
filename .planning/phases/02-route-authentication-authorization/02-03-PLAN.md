Contract this plan creates, consumed by plans 02-04 to 02-10:

- `Principal(id, roles, participant, coach_studies)`, frozen, with property `is_admin`; `is_authenticated` is removed
- `get_principal(request: Request) -> Principal`: raises the 401 envelope, or returns a verified principal
- `openwellness_api.v1.FloorRoute`: the route class every resource route has
- Test helpers: `token_for(app, *, user_id, participant=None, roles=(), coach_studies=())`, `TEST_ADMIN_ID`, `anon_client`; `client` authenticates as admin
</interfaces>

Facts verified by the planner against the current tree:
- FastAPI 0.136.3 reads and parses the body in `get_request_handler` before `solve_dependencies`. A JSON decode failure raises `RequestValidationError`; any other parse failure, such as invalid UTF-8, raises Starlette's `HTTPException(400)`. Both happen before any dependency runs.
- Probe with FastAPI 0.136.3 against today's full router table, sending body `{` with `Content-Type: application/json` as an anonymous caller to all 254 non-exempt method-and-path pairs: a router-level dependency answers 400 on 74 of them (every route with a body); a route class that verifies before calling the inner handler answers 401 on all 254, with the AIP-193 envelope. Under that route class, `/v1/auth:sendLoginCode` with `{` still answers 400, `/healthz` still answers 200, and an authenticated `{` still answers the 400 INVALID_ARGUMENT envelope.
- `include_router` rebuilds each route with `route_class_override=type(route)`, so `APIRouter(route_class=...)` on the parent has no effect, while a class set on a child's routes survives both the `v1` and the `app` include. The probe confirmed the class reaches `app.routes`.
- An `HTTPException` raised inside the wrapped handler reaches the app's registered handler, so the 401 keeps the AIP-193 envelope. `verify_access` is CPU-only, and `token_service` is a `providers.Singleton`, so calling it on the event loop does no I/O.
- `principal.py` keeps its lazy-import reason: `auth/__init__.py` imports its router, which imports `common.handlers`, which imports `deps.principal`. Import `InvalidAccessToken` inside the function.
- `is_authenticated` on `Principal` has no reader outside `principal.py` and `test_principal.py`.
- `conftest.py` provides `fakes`, `app`, `client`, `fake_email_sender`, and `seed_accounts` (a verified, login-ready `alice@example.com`). `test_auth_api.py` holds the send-then-verify shape in `_login`.
</context>
