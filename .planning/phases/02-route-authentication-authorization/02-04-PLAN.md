Contract this plan creates, consumed by plans 02-05 to 02-09:

```python
class Verdict(IntEnum):      # higher wins across columns (D-07)
    NOT_FOUND = 0
    FORBIDDEN = 1
    ALLOW = 2

class authorize:             # callable class so tests can read .module and .op
    def __init__(self, module: str, op: str) -> None: ...
    def __call__(self, request: Request, principal: Principal = Depends(get_principal)) -> "Access": ...

class Access:
    principal: Principal
    def check_record(self, entity: Any, *, name: str | None = None) -> Any: ...  # returns entity, or raises 403/404; name sets the id in the 404 text
    def scope_list(self, items: list[Any]) -> list[Any]: ...  # D-08; call before filter= and paginate
    def stamp_create(self, payload: dict[str, Any], *, parent_id: str | None) -> dict[str, Any]: ...
    def check_members(self, participant_ids: Iterable[str]) -> None: ...  # A-09-2; raises the denial 404
```

Decision rules, evaluated in this order for one request:

1. Role predicate. The admin column exists only when `admin` is in the token's roles, and the coach column only when `coach` is. The self column always exists. A column that does not exist gives no verdict: its scope and cell are never read. This is why `no_role` gets 404 on `user`, `device` and `fitbit` record ops, whose coach scope is None, while `coach_in` gets 403 on `device` and `fitbit`.
2. Scope-none rule. A column that exists and whose scope is None is FORBIDDEN: self and coach on `admin` and `app`, coach on `device`, `fitbit` and `user`. The admin column has no predicate: ALLOW if the op is in `admin_ops`, else FORBIDDEN.
3. Predicate. Otherwise predicate False is NOT_FOUND; predicate True is ALLOW if the op is in that column's cell, else FORBIDDEN; a predicate that needs a record not yet supplied is deferred.
4. Combine. At `authorize` time take the best non-deferred verdict: ALLOW proceeds; if anything is deferred the handler must supply the record; else FORBIDDEN raises 403 and NOT_FOUND raises 404. `check_record` and `scope_list` evaluate the deferred columns against the record and take the best with the earlier verdicts. `scope_list` returns the items untouched if ALLOW was already reached; otherwise it keeps the items whose verdict is ALLOW, and when `row.route` contains `{user}`, the input was non-empty and nothing remains, it raises the 404 (D-08); top-level and study-parented lists return the kept list, possibly empty.

| Predicate | No record yet | With record |
| --- | --- | --- |
| `self-user` | `{user}` equals sub; no segment: vacuous | n/a |
| `self-owner` | `{user}` equals participant claim | n/a |
| `self-participant` | `{participant}` equals claim; no segment: vacuous | n/a |
| `self-study` | `{study}` equals own study; no segment and op is list or create: vacuous; otherwise deferred | `record.id` equals own study |
| `self-device`, `self-fitbit` | list in cell: deferred; list or create otherwise: vacuous; record ops: deferred | `record.participant_id` equals claim |
| `self-member-group` | `{user}` differs from claim: False; list or create: True; record ops: deferred | claim in `record.participant_ids`, group not archived |
| `self-member-conversation` | create: vacuous; list and record ops: deferred | always False (OQ1, ADR amendment) |
| `coach-study`, `{study}` in path | `{study}` in coach_studies | n/a |
| `coach-study`, `study` row, no segment | create: vacuous; list and `:lookup`: deferred | `record.id` in coach_studies |
| `coach-study`, binding `participant` | create: owner Participant's study in coach_studies; list and record ops: deferred | `record.study_id` in coach_studies, and for an allowed patch, delete or undelete also the Participant of `record.owner` |
| `coach-study`, binding `membership` | create: vacuous, `stamp_create` checks the study; list and record ops: deferred | `record.study_id` in coach_studies |

Vacuous means "no record to hide": the predicate holds. A self predicate that uses the participant claim is False whenever the claim is empty, before any other rule, including vacuous ones. Own study: `Participant.get_by_id(claim).study_id`, fail closed on no record, empty study or archived. Participant reads go through `request.app.state.container.repositories.participant()` and are cached on the `Access`. Archived means `getattr(entity, "deleted_at", None)` is not None, in one helper (OQ3). `self-participant` holding vacuously is why a participant's `GET` or `POST /v1/studies/{study}/participants` is 403 for any study with no read: A1, developer-confirmed on 2026-11-04, the D-06 refinement in the ADR amendment.

404 text derives from the URL so it matches `not_found` and `check_parent`: `/v1/users/u/weights/abc:undelete` gives `weights/abc not found for users/u`; `/v1/devices/abc` gives `devices/abc not found`; `/v1/users/u/weights` gives `weights not found for users/u`. With `name`, the text is `{collection}/{name} not found`, exactly what `not_found(collection, name)` raises: on `/v1/studies:lookup`, name `n` gives `studies/n not found` (the id is in the body, so the URL cannot supply it). Raise `EntityNotFoundException`, and routers let it propagate. 403 uses `build_error(403, "PERMISSION_DENIED", "Permission denied.")` in an `HTTPException`. Log denials at info with principal id, module and op only.

`stamp_create` by `row.binding`: `"participant"` reads the Participant of `parent_id`, 404 when it is missing, archived or has an empty study_id, or when a non-empty supplied `study_id` differs; then writes `study_id`. `"study"` uses `parent_id` as the study, same differing-value rule. `"membership"` requires a non-empty supplied `study_id`, and for a non-admin it must be in coach_studies, else 404. All three then call `stamp_audit(payload, parent_id=parent_id, principal=self.principal)`. `None` (`admin`, `app`, `device`, `fitbit`, `participant`, `study`, `study_message`, `user`): raises `ValueError` naming the module. These rows have no owner's Participant to bind through, their routers keep their own create, and the error surfaces as a 500 in the matrix rather than writing an unbound record.

`check_members` (A-09-2, developer-decided on 2026-11-04): returns at once for a caller with the admin role, reading nothing. Otherwise each entry goes through the same cached Participant read and must resolve to a record that is not archived and whose non-empty `study_id` is in `coach_studies`, by exact string; the first entry that does not raises the URL-derived 404, so unknown, archived and cross-study ids are indistinguishable from each other and from a denial on that URL. Only `participant_group` writes call it.
