Facts verified by the planner against the current tree:
- Mongo `create` ignores a caller-chosen id: `entity.id = str(result.inserted_id)`. Use the id on the returned entity, in order: Study, then User, then Participant (`study_id`, `user_id`), then save the User with `roles.participant.pid`. `MongoParticipantRepository._to_doc` needs `study_id` to be a valid ObjectId, and a created Study id is.
- `user`, `study` and `participant` providers depend only on `collection_repository`, so the seed needs Mongo and never opens Couchbase. `ApplicationContainer` plus `container.app_config.override(providers.Object(AppConfig()))` is how `main.py` wires them. Do not call `entity_repository().initialize()`.
- `Study` requires `app_id`, `name`, `time_created`; `User` requires `email`, `is_active`, `username`; `Participant.is_active` defaults False.
- Ports for idempotency: `UserRepository.get_by_email`, `StudyRepository.get_by_name`, `ParticipantRepository.get_by_num_study_id`. The in-memory fakes implement all three.
- `pydantic.EmailStr` rejects special-use domains such as `.test`, while `example.com` passes and existing tests use it. `test_no_print_call_in_core_api_or_scheduler_src` scans `backend/api/src`, so a script under `backend/api/scripts` may print.
- `backend/Dockerfile` copies `api/` wholesale, so without a `.dockerignore` line the script ships in the image. `backend/.dockerignore` is relative to the `./backend` build context.
- Client-side bases: the dashboard reads `VITE_API_BASE_URL`, default `http://127.0.0.1:8000/v1`. Android's default is `http://10.0.2.2:8000/v1/`. iOS hardcodes `http://localhost:8000/v1/` in `iOSApp.swift`. So the UAT runs the API on port 8000 and needs no client config change.
- `SmtpEmailSender` calls `starttls()` only when `SMTP_USE_TLS` is true and logs in only when a username is set, so `SMTP_USE_TLS=false` with host `localhost` and port `1025` reaches a local sink.
- Node here is v26, and CI pins 22 because Node 25+ built-in localStorage breaks the jsdom suites. The proven dashboard test command therefore runs in a `node:22-bookworm-slim` container.
- Count-gate baselines at HEAD, run during planning: `grep -c 'recorded grep' .planning/ROADMAP.md` is 0; `grep -c 'logging-only pass' .planning/ROADMAP.md` is 1; `grep -c 'API_ENABLE_DOCS' .planning/ROADMAP.md` is 0; `grep -c '^- \[Phase 2\]' .planning/STATE.md` is 2; `grep -c '^api/scripts' backend/.dockerignore` is 0.
