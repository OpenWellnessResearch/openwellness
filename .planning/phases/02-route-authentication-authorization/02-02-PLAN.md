## Flagged assumptions

Task 2 writes each of these into the amendment. Rows marked developer-confirmed were settled by the developer on 2026-11-04 and are closed. The other rows are planner defaults: tell the developer if any should change; each is local to the engine or one router.

| ID | Open decision | Planned default | Status | Rating |
| --- | ------------- | --------------- | ------ | ------ |
| A1 | Segment-less create and list by a caller whose cell lacks them | 403: there is no record to hide, so the predicate holds vacuously (`POST /v1/users`, `GET /v1/users`, `POST /v1/devices`, `GET /v1/studies/{study}/participants` for a participant). A participant's `GET` or `POST /v1/studies/{study}/participants` answers 403 for any study: the answer is the same whichever study is named, and no read is needed. This refines D-06 | Developer-confirmed on 2026-11-04 | reversible |
| A2 | Top-level lists with a filter predicate (`device`, `study`, `conversation`) | Filter silently and answer 200, possibly empty; D-08's 404 applies only to `users/{user}/...` lists | Planner default | reversible |
| A3 | Forbidden keys in a patch body | Silently ignored, matching `extra="ignore"` and keeping the wire stable | Developer-confirmed on 2026-11-04 | reversible |
| A4 | Routes outside the 36x7 table | `POST /v1/conversations:search` is op `list`; `POST /v1/studies:lookup` is op `get`; both scope-filtered | Developer-confirmed on 2026-11-04 | reversible |
| A5 | Deactivated user or logout with a live access token | Accept the 930 s window from ADR 0006; no per-request user read | Developer-confirmed on 2026-11-04 | reversible |
| OQ1 | `self-member-conversation` | Keep the cells as ADR 0007 states and make the predicate match nothing until Phase 6, because the domain `Conversation` does not carry `channels`; no participant data leaks | Developer-confirmed on 2026-11-04 | reversible |
| OQ3 | Archived Participant or group | One helper reads `getattr(entity, "deleted_at", None)`; legacy adapters never set it, so it takes effect with Phase 5 | Research's recommendation, kept as planned on 2026-11-04 | reversible |
| A-09-1 | `participant_group` list | Means "groups the `{user}` segment is a member of" for every caller, then the caller's scope applies | Planner default | reversible |
| A-02-1 | Coach owner-scoped list for an out-of-study participant with no records in the requested range | D-08 stands: an empty 200 that exposes no data. AUTH-05 and success criterion 3 name this case (Task 3) | Developer-decided on 2026-11-04 | reversible |
| A-09-2 | `participantIds` on a coach's `participant_group` write | Every entry must be a participant whose study is in `coach_studies`, else 404 identical to the normal denial; admins are not restricted; Participant is read per entry on group writes only | Developer-decided on 2026-11-04 | reversible |

Planner note for the developer: research called OQ1 not computable through today's ports. `ConversationRepository.get_for_filters` with `Conversation.Filter.Type.CHANNELS` can read stored channels on Couchbase, so a live predicate for legacy data is a small swap inside `authz/engine.py` if wanted. The developer confirmed fail-closed until Phase 6 on 2026-11-04: no client reads conversations today, and API-created conversations store no channels, so a live predicate would only serve legacy documents.
