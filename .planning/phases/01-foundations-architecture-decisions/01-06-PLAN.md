<objective>
Put refresh-session persistence behind a datastore-neutral `RefreshSessionRepository` port in core, with a Mongo adapter that keeps today's document shape. The API's `RefreshSessionStore` keeps the single-use rotation and reuse-detection policy, written once, and stops touching pymongo (FOUND-05).

Purpose: Phase 3 adds the refresh grace window to one policy implementation, and Phase 4 adds a Postgres adapter for the same port. The security logic is not duplicated per datastore (research ARCHITECTURE.md, "Auth persistence").
Output: The port with its record type, the Mongo adapter, container wiring, the refactored store, and updated fixtures.
</objective>

Facts verified by the planner:
- The public API of RefreshSessionStore used by AuthService is: `create(...)`, `consume_for_rotation(...)`, `revoke_by_hash(...)`, `revoke_family(...)`, `revoke_all_for_user(...)`. Exceptions are `RefreshInvalid` and `RefreshReuse`, and `RotationResult` is a frozen dataclass. AuthService does not change in this plan.
- RefreshSessionStore is constructed in exactly three test places: backend/api/tests/test_session_store.py `_store()`, backend/api/tests/conftest.py (app fixture), and backend/api/tests/test_auth_service.py `_Ctx` (line ~177). All three call `ensure_indexes()`, and main.py lifespan calls it at line 66.
- The lifespan currently builds the collection handle as `container.repositories.collection_repository()[s.refresh_collection]` and overrides `auth_container.refresh_collection` (a `providers.Dependency`). session_store is a `providers.Factory(RefreshSessionStore, collection=refresh_collection, clock=clock)`.
- `AuthSettings.refresh_collection` defaults to "auth_refresh_sessions". `grep -rn refresh_collection backend/api/src | wc -l` gives 8 at HEAD. It is not in .env.example or any README.
- test_session_store.py (16 tests) wraps mongomock collections to inject a lost CAS race (a wrapped update_one) and a failed child insert (a wrapped insert_one). The adapter must call exactly those collection methods so the wrappers still bite. Plan 01-01 already changed FUTURE to a far-future date there.
- core `providers.py` exports `DISingleton`. dependency-injector supports `provider.provided["key"]` item access. `MDBCollectionRepository.__getitem__` returns a pymongo Collection. pymongo MongoClient construction does not connect.
- `object_id_or_none` exists in mongo_base_repository.py (plan 01-03).
- test_auth_container.py asserts the provider names (`session_store`, etc.) and overrides `session_store` with an object; neither changes.
- Design note: `RefreshSession` lives in the port module as the port's record type, not in domain/models. It is an auth persistence record with no business behavior, and keeping it next to the port means Phase 4 imports one module.
