<objective>
Define the datastore, Redis and shared settings once, in `core`. Every service loads them from one documented `.env` at the repository root, whether it starts under docker compose or as `uvicorn`/`celery` directly from any working directory. Precedence is environment, then `.env`, then defaults (FOUND-02, FOUND-03; implements D-17 and D-18).

Purpose: Today `backend/api/.../config.py` and `backend/scheduler/.../config.py` each carry identical CouchbaseSettings/SyncGatewaySettings/MongoSettings/AppConfig classes, and nothing sets `env_file`, so running a service directly ignores `.env`. backend/README.md even documents a different location (`backend/.env`).
Output: `openwellness_core.infrastructure.config.settings`, thinned service configs, tests, and corrected docs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator filesystem to process config | `.env` holds secrets and datastore URLs read at startup |
| Developer machine to test run | A local `.env` may point at live data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Information disclosure | repo-root `.env` | high | mitigate | `.env` stays gitignored (.gitignore lines 48-50); tests never create or modify it; docs say "never commit .env" |
| T-01-05 | Tampering | OPENWELLNESS_ENV_FILE override | low | accept | Set only by the operator who already controls the process environment; no privilege change |
| T-01-06 | Information disclosure / Tampering | Test runs reading a developer's `.env` (live Mongo URL, secrets) | medium | mitigate | Conftests pin the override to os.devnull before imports; core tests pass an explicit `_env_file` |
| T-01-07 | Elevation | Default datastore credentials | medium | mitigate | PostgresSettings.url defaults to an empty string; the existing Couchbase defaults are unchanged here (the secret boot guard is a later phase) |
| T-01-SC | Tampering | pip dependency added to core | low | accept | `pydantic-settings` is already locked in backend/uv.lock and used by api/scheduler; the lock diff adds no package (acceptance gate) |
</threat_model>
