<objective>
Remove datastore types from the domain (FOUND-04). `Participant` carries plain string ids, the Mongo adapter coerces them to and from ObjectId, and the API stops importing `bson`.

Purpose: The Postgres adapters (Phases 4 and 5) and the PowerSync schema (Phase 6) need a domain with text ids (ADR 0001 / D-11), and the Dependency Rule forbids driver types in `domain/`.
Output: Updated Participant entity, Mongo participant adapter, participant router and schemas, plus end-to-end tests.
</objective>

Facts verified by the planner:
- The only bson imports under domain/ or application/ are in domain/models/participant.py: `assigned_coach_id: Optional[ObjectId]`, `user_id: Optional[ObjectId]`, and `study_id: ObjectId = field(default_factory=ObjectId)`, which makes a random id by default.
- The Mongo persistence model is `backend/core/src/openwellness_core/adapters/mongo/model/mongo_participant.py` (`MongoParticipant`, aliases assignedCoachId / userId / studyId, typed Any). `MongoBaseEntity._stringify_objectid_fields` already turns every ObjectId into a str on read, so reads need no change; only writes must convert back.
- `MongoBaseRepository._to_doc(entity)` feeds create (insert_one), save ($set) and archive. Overriding `_to_doc` in MongoParticipantRepository covers every write path.
- api bson imports: resources/participant.py (`_coerce_object_ids`, `ObjectId(study)` in create, the ObjectId branch in `_to_dict`), and schemas/_base.py (try-import plus `ObjectIdField`, `_to_object_id`, `_from_object_id`). `ObjectIdField` has zero users (grep across backend). The bson mention inside errors/handlers.py is a docstring only, and tests/test_error_mapping.py legitimately builds an ObjectId to test serialization; leave both.
- After plan 01-03, `object_id_or_none` lives in mongo_base_repository.py, and the participant study queries already return []/None for malformed ids.
- backend/api/tests/conftest.py seed_accounts passes `user_id=login_user_id` and `user_id=reg_user_id` with `# type: ignore[arg-type]` comments that explain a stringified-ObjectId workaround. Those become stale.
- The auth service reads `str(participant.user_id)` in `_eligible_registration_target`; it still works with str.
- Participant construction sites (grep at revision time): resources/participant.py create (`ParticipantEntity(**payload)` with study_id from the path), the Mongo read path, and two fixtures in backend/api/tests/conftest.py over fake repos. The scheduler never constructs one. So the new `study_id` default of "" is reached only by code that omits the study, which the adapter must refuse rather than store.
- Today `MongoBaseEntity._stringify_objectid_fields` also runs inside `from_domain`, so writes through this adapter store reference ids as strings even after the router's ObjectId coercion. The `_to_doc` override below fixes that, which test (1) proves.
</context>
