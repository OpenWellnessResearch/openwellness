All three call `ensure_indexes()`, and main.py lifespan calls it at line 66.
- The api test `app` fixture bypasses the real lifespan, so Task 1's verify runs a one-off boot smoke through it and Task 2 commits a boot test that enters it. The smoke command in Task 1 was run at HEAD on 2026-10-30 and printed `boot-ok`; with `RefreshSessionStore.ensure_indexes` deleted (the old lifespan over the new store) it fails with an AttributeError traceback. Proven at HEAD by the planner (2026-10-30, a throwaway script, nothing committed): with `openwellness_api.main.ApplicationContainer` replaced by a factory that builds the real container and overrides `repositories.entity_repository` with `providers.Object(MagicMock())` and `repositories.collection_repository` with `providers.Object(mongomock.MongoClient()["boot"])`, plus env API_AUTH_JWT_SECRET and API_AUTH_CODE_PEPPER (40 chars each), API_AUTH_REFRESH_COLLECTION=custom_sessions and REDIS_URL=redis://127.0.0.1:1/0, `with TestClient(main.create_app())` runs the whole lifespan: /healthz returns 200, the Redis ping only logs a warning, and the custom_sessions collection gets the indexes `_id_`, `ix_family_id`, `ix_user_id`, `ttl_expires_at` and `uq_token_hash`. The api conftest pins OPENWELLNESS_ENV_FILE to os.devnull (plan 01-02), so no developer .env is read.
- The lifespan currently builds the collection handle as `container.repositories.collection_repository()[s.refresh_collection]` (main.py lines 62-64) and overrides the AuthContainer collection Dependency (auth_container.py line 97). session_store is a `providers.Factory(RefreshSessionStore, collection=..., clock=clock)` (line 98).
